# Agent guidelines

This repository is a sample of a Kotlin Multiplatform library that uses the Firebase Apple SDK through the Kotlin Gradle
Plugin's SwiftPM import (`swiftPMDependencies {}`), and a SwiftUI app for iOS and macOS that uses the library.
People read it to learn SwiftPM import, so the code has to be correct, small and easy to follow.

Read `README.md` first. It explains the project structure and the setup.

## Layout

- `kotlin-library/` - The KMP module, built as the static `KotlinLibrary` framework for `iosArm64`,
  `iosSimulatorArm64` and `macosArm64`.
  - `src/commonMain/` - The `FirebaseKMP` API that Swift calls, and its mock.
  - `src/appleMain/` - The Firebase implementation, one service class per product, and one sample per product.
  - `src/iosMain/` - Samples for products that Firebase ships for iOS only.
- `kotlin-library/FirebaseAIBridge/` - A local Swift package that wraps the Swift-only `FirebaseAILogic` SDK in
  `@objc` classes so Kotlin can call it.
- `appleApp/` - The SwiftUI app. One multiplatform target and scheme, both named `appleApp`.
- `appleApp/KotlinMultiplatformLinkedPackage/` - Generated by the Kotlin Gradle Plugin and committed. The files are
  read-only. Never edit them by hand.
- `.swiftpm-locks/default/swiftImport/Package.resolved` - The lock file for the Kotlin side. Commit it whenever it
  changes. Everything else under `.swiftpm-locks/` is generated or ignored.

## Verifying a change

There are no tests yet, so build what your change touches. A change to the Kotlin API touches everything.

```shell
# Kotlin, all targets
./gradlew :kotlin-library:compileKotlinIosSimulatorArm64 :kotlin-library:compileKotlinIosArm64 :kotlin-library:compileKotlinMacosArm64

# The app on both platforms (the Run Script phase runs Gradle)
xcodebuild build -project appleApp/appleApp.xcodeproj -scheme appleApp -sdk iphonesimulator -arch arm64 -derivedDataPath ./build CODE_SIGNING_ALLOWED=NO
xcodebuild build -project appleApp/appleApp.xcodeproj -scheme appleApp -destination 'platform=macOS,arch=arm64' -derivedDataPath ./build CODE_SIGNING_ALLOWED=NO
```

After you change `swiftPMDependencies {}`, the first Xcode build regenerates `KotlinMultiplatformLinkedPackage` and
fails with "Synthetic linkage package files changed during the build". Build again, then commit the regenerated files
and the lock files.

Imported Objective-C APIs live in the Kotlin package `swiftPMImport.org.jetbrains.kotlin.firebase.sample.kotlin.library`.
Before you write Kotlin against one, check its imported signature. Selector names, nullability and Kotlin parameter
names are easy to guess wrong:

```shell
~/.konan/kotlin-native-prebuilt-macos-aarch64-<kotlin version>/bin/klib dump-metadata \
  kotlin-library/build/classes/kotlin/iosSimulatorArm64/main/cinterop/kotlin-library-cinterop-swiftPMImport
```

## SwiftPM import pitfalls

- Declare only the products that Kotlin code uses directly. The plugin imports the Clang modules of transitive
  dependencies (`FirebaseCore`, `FirebaseInstallations`, ...) on its own.
- Kotlin only sees Objective-C compatible APIs. Swift products with `@objc` APIs, such as `FirebaseFunctions`, work
  directly. For a Swift-only product, add `@objc` wrappers to `FirebaseAIBridge` or another local package and declare
  it with `localSwiftPackage(...)`.
- Limit a product that Firebase ships only for iOS with `product("...", platforms = setOf(iOS()))` and put its code in
  `iosMain`. App Distribution, In-App Messaging and Performance are iOS-only.
- Keep versions in sync: the Firebase version in `gradle/libs.versions.toml` and `FirebaseAIBridge/Package.swift`,
  and the deployment targets (iOS 18, macOS 15) in `kotlin-library/build.gradle.kts`, `FirebaseAIBridge/Package.swift`
  and the Xcode project.
- Don't add `kotlin.mpp.enableCInteropCommonization`. The plugin turns it on when SwiftPM dependencies exist.
- The CocoaPods plugin can't be combined with `swiftPMDependencies {}`.
- Don't run Gradle from the command line while the IDE is syncing the project. Both run `xcodebuild` in the same
  `build/kotlin/swiftPMXcodeDumps` directory and fail with "database is locked".

## Xcode project rules

- `MemberImportVisibility` is on. Import every module whose members a file uses. Views don't touch Kotlin types;
  `FirebaseService` exposes what they need.
- `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` works here because Swift only calls Kotlin and never subclasses or
  implements Kotlin types.
- Keep `ENABLE_USER_SCRIPT_SANDBOXING = NO`. The Run Script phase runs Gradle, which reads and writes outside the
  sandbox.
- Keep `DEAD_CODE_STRIPPING = YES`. FirebaseCore declares constants it never defines, and the macOS link fails on their
  unused cinterop getters without stripping.
- iOS-only APIs (UIKit, keyboard modifiers, `iosMain` declarations) must be behind `#if os(iOS)`, because the same
  target builds for macOS.
- The bundle ID stays `org.jetbrains.kotlin.firebase.sample.iosApp`. It has to match `GoogleService-Info.plist`.
- The project uses buildable folders, so new Swift files in `appleApp/appleApp/` are picked up without editing
  `project.pbxproj`.
- `FirebaseService` turns the Kotlin callbacks into `async` functions. Kotlin completion blocks are `@Sendable` in Swift.
- Previews use `FirebaseService.preview(...)`, which is backed by the Kotlin mock. Previews never call Firebase.

## Writing style

- Comments and docs are short and plain. Say what the code does and why, not how impressive it is.
- Keep `README.md` in sync with the code. Every claim in it should be something the sample shows.
- Use small, focused commits with a short imperative subject, for example "Add a Cloud Functions sample".
